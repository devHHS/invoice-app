# W03 — 계층과 DTO

`goal`: Entity가 외부로 노출되지 않는다
`scope`: DTO 분리, 계층 책임 명확화, 입력 검증, `InvoiceNotFoundException` 정의(W04 월요일 몫 앞당김)
`out_of_scope`: 전역 예외 처리(`@RestControllerAdvice`, W04), 모듈 분리 (W05)

## 일정

`요일` 라벨은 캘린더 요일이 아니라 세션 순서 라벨이다 — 진행 속도에 맞춰 앞당기거나 밀려도 된다. `InvoiceRequest`/`InvoiceResponse` 생성(원래 월요일 몫)은 이미 완료돼 아래 표에서 제외했다 — 상세는 `docs/logs/W03.md` 참고.

## 이해 체크

- Entity를 그대로 반환하면 뭐가 문제인가? **3가지** 대라.
- 변환 로직이 Controller가 아니라 Service에 있어야 하는 이유는?
- 각 계층의 책임을 한 문장씩 말하라.

## 자주 막히는 곳

**"DTO가 Entity랑 똑같은데 왜 만들지?"** — 지금은 똑같다. 4주 뒤 필드가 늘고 응답에서 숨길 게 생기면 달라진다. 지금 분리해두는 것이 나중을 위한 것임을 이해하고 넘어간다.

**`@Valid`가 안 먹힘** — Controller 파라미터에 붙였는지 확인. Service에 붙이면 동작하지 않는다.
