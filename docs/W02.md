# W02 — CRUD 완성

`goal`: Postman으로 CRUD 4개가 동작한다
`scope`: Repository, Service, Controller 3계층
`out_of_scope`: DTO, 예외 처리, 검증 (W03~W04)

## 일정

| 요일 | 할 일 | 성공 기준 |
|---|---|---|
| 월 | `InvoiceRepository extends JpaRepository<Invoice, Long>` | 컴파일 통과 (구현체 없음) |
| 화 | `InvoiceService` — save, findAll. **생성자 주입** | 필드 주입 쓰지 않기 |
| 수 | `InvoiceController` — POST, GET | Postman 저장·조회 성공 |
| 목 | **Python 트랙** — 딕셔너리, 리스트 컴프리헨션 | — |

| 토 | GET(단건), PUT, DELETE + `docker exec`로 psql 접속해 데이터 직접 확인 | SELECT로 행 확인 |
| 일 | 회고 커밋 | — |

## 이해 체크

- Repository 구현체를 안 썼는데 왜 동작하는가? (Panache와 같은 원리)
- `@Autowired` 필드 주입 대신 생성자 주입을 쓰는 이유 두 가지는?
- POST와 PUT의 차이는? 왜 나눠 쓰는가?

## 자주 막히는 곳

**JSON 역직렬화 실패** — Entity에 기본 생성자가 없으면 발생. Lombok `@NoArgsConstructor` 확인.

**`findById`가 `Optional`을 반환** — 여기서 바로 `.get()`을 부르고 싶어지지만, W04에서 예외 처리로 다룬다. 지금은 `orElseThrow()` 정도로 두고 넘어간다.
