**한 일**
- Month 3 방향 논의: 처음엔 "테스트 → 인증/인가 → Angular" 순서를 제안했으나, 사용자가 "이 프로젝트는 백엔드 전용이 아니다"라고 지적 — `MISSION.md`를 다시 확인해 Angular(원래 계획상 지금 시점)를 먼저 넣는 쪽으로 재고했다가, 사용자가 "코드 작성과 동시에 유닛 테스트 작성이 실무 기본"이라는 근거로 재반박 — 최종적으로 **Month 3(테스트) → Month 4(Angular) → Month 5(인증/인가) → Month 6(FastAPI+AI)** 순서로 합의
- `docs/CURRICULUM.md`에 Month 3(JUnit 5 + Mockito + MockMvc) 4개 Phase 상세 작성 — `VendorService`(단순) → `InvoiceService`(복잡한 분기) → Controller(MockMvc) → 마무리 순
- FastAPI 서비스의 목적이 문서에 없었다는 걸 확인하고, 사용자에게 직접 물어 확정: 영수증 자동 인식(OCR), 지출 분류, 그 외 기능 1개(미정) — `MISSION.md`에 기록
- 전체 로드맵(Month 3~6 + `MISSION.md`의 "범위 밖" 목록 Redis/Kafka/K8s/MSA/React/GraphQL까지 전부 포함) 완료까지 걸릴 기간을 실제 커밋 기록(Month 1: 25일, Month 2: 13일) 기반으로 추정 — 핵심 로드맵만 약 3~4.5개월, 범위 밖까지 전부 포함하면 총 8개월~1년 이상으로 추정된다고 설명, "여러 개를 겉핥기"가 될 위험을 짚음
- 사용자가 "그럼 범위 밖 항목은 다른 프로젝트로 하는 게 낫냐"고 재확인 — React/MSA 분리는 이 프로젝트에서 영구 제외(다른 프로젝트가 적합), Redis/Kafka/K8s는 이 프로젝트에 나중에 자연스러운 필요(AI 서비스 이벤트 트리거, 캐싱, 배포 업그레이드)가 생기면 재논의 가능하다고 구분 — `MISSION.md` "Out of scope" 섹션을 이 기준으로 재작성
