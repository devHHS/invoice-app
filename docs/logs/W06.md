## Phase 2 계속 — Invoice에 vendor 필드 추가 (수요일, 시간 부족으로 최소 범위)

**한 일**
- 레슨 0020 작성(`@ManyToOne`/`@JoinColumn`/owning side 개념), `reference/0001`에 용어 추가
- 시간이 15분뿐이라 레슨 0020의 힌트 1~2만 진행: `VendorRepository`(신규, 커스텀 쿼리 없는 기본 형태) + `Invoice.java`에 `vendor` 필드(`@ManyToOne` + `@JoinColumn(name = "vendor_id")`) 추가, `storeName`은 그대로 유지(추가만 하고 아직 안 지움 — Month 1 DTO 도입 때와 같은 점진적 전환 전략)
- DTO(`InvoiceRequest`/`InvoiceResponse`) 수정, Service 연결(`VendorRepository` 주입 + 조회 로직), psql 검증(힌트 3~5)은 다음 세션으로 연기

**막혔던 것과 원인**
- `VendorRepository`를 `class`로 선언해 `no interface expected here` 컴파일 에러 — `JpaRepository`는 인터페이스인데 `extends`로 클래스가 상속하려 해서 발생. `InvoiceRepository.java`와 비교해보라는 힌트로 스스로 `interface`로 수정
- `Invoice.java`에 `vendor` 필드는 추가했으나 처음엔 `getVendor()`/`setVendor()`를 빠뜨림 — 컴파일 에러는 아니었지만(아직 아무도 안 씀) 다음 레슨에서 바로 필요하다는 점을 짚어주자 바로 추가

**다음에 이어질 것**
- 레슨 0020 힌트 3(InvoiceRequest에 `vendorId`, InvoiceResponse에 `vendorName` 추가) ~ 힌트 5(psql로 `vendor` 행 만들고 연결 검증)부터 이어서
- 커밋 메시지 추천: `feat: add ManyToOne mapping from Invoice to Vendor`

## Phase 2 계속 — Invoice-Vendor 연결 로직 완성, 레슨 0020 완료 (목요일)

**한 일**
- 레슨 0020 힌트 3(`InvoiceRequest.vendorId`, `InvoiceResponse.vendorName` 추가) ~ 힌트 5(psql 검증) 전부 완료
- `InvoiceService`에 `VendorRepository` 주입, `toEntity()`에서 `vendorId`로 `Vendor` 조회 후 `invoice.setVendor(...)`, `toResponse()`에서 `vendorName` 세팅 — `IntelliJ의 "@JoinColumn 을 실무에서 이렇게 점진적으로 도입하는지"` 질문에 expand-contract 마이그레이션 패턴으로 답변(이 프로젝트엔 실질적 리스크 없지만 실무 습관 연습 차원임을 확인)
- psql로 `vendor`에 스타벅스 행(`id=1`) 직접 insert 후, `requests.http`에 `vendorId: 1` 포함한 POST로 실제 연결 확인(`vendorName: "스타벅스"` 응답, DB의 `invoice.vendor_id=1` 확인) + 기존처럼 `vendorId` 없는 POST도 여전히 정상 동작(`vendorName: null`)함을 확인 — 하위 호환 유지 검증 완료
- `docs/CURRICULUM.md` Phase 2 체크리스트 갱신(`Vendor` 엔티티, `@ManyToOne` 매핑 완료 처리, `storeName` 제거 항목 신규 분리)

**막혔던 것과 원인**
- `InvoiceService` 생성자에 `VendorRepository`를 추가할 때, 기존 생성자를 고치는 대신 **별도의 두 번째 생성자**(`InvoiceService(VendorRepository)`)를 만들어 `variable ... might not have been initialized` 에러 — "생성자는 실행 시점에 하나만 선택되어 호출된다"는 실행 모델을 아직 직관적으로 못 잡고 있음, 파라미터 두 개짜리 생성자 하나로 합치라는 설명 후 해결 (`learning-records/0013`)
- `toEntity()`에서 `vendorRepository.findById(...)`를 두 번 호출(한 번은 존재 확인만 하고 버림, 한 번은 `.get()`으로 다시 조회) — 첫 호출의 반환값을 변수로 받아 재사용하라고 짚어주자 바로 수정
- IntelliJ가 `@JoinColumn`에 "Cannot resolve column 'vendor_id'" 경고 — 실제 DB엔 컬럼이 이미 있었음(psql로 확인), 원인은 IntelliJ Database 툴 창의 스키마 캐시가 앱 재시작과 별개로 갱신 안 된 것 — 데이터소스 Refresh로 해결 (`docs/CURRICULUM.md` "자주 막히는 곳"에 기록)
- 테스트 중 JSON body의 `vendorId` 줄을 지우다 트레일링 콤마를 남겨 400(JSON parse error) — 실제 파일 내용을 다시 확인해 정상 상태임을 스스로 재확인 후 재실행하여 해결

**다음에 이어질 것**
- `Invoice.storeName` 필드 완전 제거 + `InvoiceRepository`의 검색 쿼리 메서드를 `findAllByVendor_StoreNameContaining`처럼 연관관계 기준으로 전환 — 새 레슨(0021) 예정
- 커밋 메시지 추천: `feat: wire Invoice-Vendor lookup in service and DTOs`
