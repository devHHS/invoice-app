## Phase 2 착수 — Vendor Entity 작성 (화요일)

**한 일**
- 레슨 0019 작성(왜 문자열 대신 별도 Entity로 정규화하는가), `reference/0001`에 "정규화/연관관계" 용어 추가
- `Vendor.java`(`com.ham.invoiceapp.vendor`) 파일 안 빈칸+주석 스캐폴딩으로 제공 — `id`, `storeName` 필드/no-args 생성자/getter·setter를 `Invoice.java` 패턴 그대로 따라 직접 작성 완료, `./mvnw compile` 통과 확인
- `Vendor`는 아직 `Invoice`와 연결하지 않은 독립 Entity 상태 (연관관계 매핑은 다음 레슨)

**막혔던 것과 원인**
- "`Invoice.storeName`은 그대로 두고 나중에 그 컬럼 자체가 FK가 되는 거냐"는 오개념 — 텍스트 설명(컬럼명 중심)으로는 이해 안 됨, 도서관 대출카드/회원번호 비유로 바꾸자 "`invoice`에는 `vendor_id`가 들어가고 그걸로 `vendor`의 이름을 조회한다"고 스스로 정확히 재진술함 (`learning-records/0012`)
- no-args 생성자가 필요한 이유(Hibernate가 빈 객체 생성 후 setter로 채우는 2단계 방식)를 재질문 — record의 불변성과 왜 안 맞는지 다시 설명

**다음에 이어질 것**
- `Invoice.storeName`(String) 필드를 제거하고 `private Vendor vendor;`로 교체, `@ManyToOne` + `@JoinColumn(name = "vendor_id")` 매핑 — 레슨 0020 예정
- `Vendor.java`는 오늘 그대로 커밋 가능
- 커밋 메시지 추천: `feat: add standalone Vendor entity in vendor package`
