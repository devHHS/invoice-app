## 수요일 — InvoiceController (POST, GET)

**한 일**
- `InvoiceController` 작성: `@RestController` + 클래스 레벨 `@RequestMapping("/invoices")`, `InvoiceService` 생성자 주입
- `POST /invoices`(`saveInvoice`, `@RequestBody Invoice invoice` → `invoiceService.save(invoice)`), `GET /invoices`(`findAll` → `invoiceService.findAll()`) 두 엔드포인트 작성
- REST 컨벤션 정리: URL 경로는 명사(리소스)로, 동작은 HTTP 메서드로 표현 — `@PostMapping("/saveInvoice")`나 `/invoices/save`처럼 경로에 동사를 넣는 건 컨벤션 위반이라는 점을 클래스 레벨 vs 메서드 레벨 경로 조합 예시로 확인
- Postman 사용법 학습 후, 대안으로 curl과 IntelliJ 내장 HTTP 클라이언트(`requests.http`) 소개받고 직접 파일 생성 — POST/GET 두 요청 모두 정상 동작 확인 (응답에 `id` 채워짐)
- 브라우저 개발자 도구로 확인 가능 여부도 짚음: GET은 주소창으로 가능, POST는 Console에서 `fetch()`로만 가능하나 실무에서는 잘 안 씀

## 토요일 — GET(단건), PUT, DELETE + psql 확인 (금요일과 같은 세션에 진행)

**한 일**
- `InvoiceService`에 `findById`(`orElseThrow()`), `update`(`setId(id)` 후 `save()` 재사용), `delete`(`deleteById()`) 세 메서드 추가
- `InvoiceController`에 `GET /invoices/{id}`, `PUT /invoices/{id}`, `DELETE /invoices/{id}` 세 엔드포인트 추가 — `@PathVariable`/`@RequestBody` 조합
- `update` 메서드에서 `id`엔 `@RequestBody`, `invoice`엔 애노테이션 없음으로 잘못 짠 것을 `findById`/`deleteById`와 비교해서 스스로 발견 → `@PathVariable Long id, @RequestBody Invoice invoice`로 직접 수정
- `save()`가 id 유무로 INSERT/UPDATE를 자동 판단한다는 것, PUT에서 Body의 id보다 URL의 id를 신뢰해야 하는 이유(파라미터 변조 방지)를 깊게 다룸 — id를 UUID로 바꿔도 이 원리는 그대로 성립한다는 것까지 확인 (`learning-records/0005`, W01 토요일에 보류했던 "id 노출=인가 문제" 논의와 연결됨)
- `requests.http`에 단건 조회/수정/삭제 요청 추가, 전부 정상 동작 확인
- `docker exec`로 psql 접속해 `SELECT * FROM invoice;`로 DB 반영 직접 확인 (삭제 후 행이 사라짐까지 확인)
- 부수 질문: Spring "cross-session messaging" 기능이 실제 존재하는지 확인 (Claude Code 자체 기능 질문, 미션과 무관해 짧게 다루고 복귀)
